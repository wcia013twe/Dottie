# Learner profile v1 (additive, local)

Producer: `scripts/learner_intelligence.py`. Consumer: `web/learn/intelligence.js`, via read-only `GET /api/learner-profile`. This is separate from the existing demo, director and harness wire formats; those remain unchanged.

The evidence-event schema normalizes explicitly confirmed learner outcomes. IDs are immutable; conflicting IDs are rejected. Learner identity and synthetic source flags must match the store. Event time requires an explicit timezone. A null trace_id means no MLflow trace is linked; fixture trace IDs are not cloud references.

The profile contains six ordered categories (braille, tactile, instructions, answering, transfer, interests), evidence, numeric counts, optional session-progress charts, concise rationale and revision history. Percentages are computed from counts. Rationale is a short evidence explanation, not model chain of thought. Unknown data remains unknown. A minimum of three comparable observations per session is an MVP display threshold, not scientific validation.

Publishing rule: compare category status, finding, action, reasoning, metric and chart, plus quick stats and the optional Genie summary. Unchanged or provenance-only passes save a processing checkpoint without creating an epoch. Published profiles remain immutable until another meaningful publication. Rows under different target/task/condition keys never form one trend; unspecified difficulty prevents a cross-session chart. Deferred responses and device failures are retained in evidence, excluded from percentages, and never graded as incorrect. Preference events require alternatives to have been available.

Confirmed, non-synthetic events now sync to `workspace.magneto.learner_observations_v1` through the existing SQL warehouse. Profiles/checkpoints and a pending-write buffer remain local in `.local/learner-intelligence/` (ignored by Git), with atomic replacement and a process-local lock. Run one local server writer. No distributed job is deployed. The default endpoint always serves real evidence, including an epoch-zero/null-update empty state. `?mode=mock` returns only an isolated fixture and never writes live records. `GET /api/learner-profile/status` reports SQL feed connectivity and the verified Genie availability, separate from feed integration. Story Mode uses anonymous session IDs; linking sessions to a persistent learner is a future explicit identity contract. Local browser facts stay separate.

Migration: initial About me hardcoded fixtures become profile JSON produced by this workflow. No legacy producer payload changes. Future Genie/model producers must validate this format plus semantic invariants (counts, identity, comparison, provenance); do not replace it with unvalidated generated HTML. Use a new version for incompatible changes and update producer, renderer, fixtures and checks together.

Run `npm run check:intelligence` and `npm run check:contracts`.

Cloud adapter: `scripts/learner_cloud.py`. Source is restricted to the configured workspace/table. Writes reject synthetic/unconfirmed events and conflicting immutable event IDs; reads are parameterized and reject truncated/chunked results before profile publication. No access permissions were changed.

## Optional judged producer

`scripts/learner_judged_updater.py` is an opt-in CLI producer of the same profile schema. Code derives all counts, comparison groups, identity and evidence IDs. A hosted LLM may propose only finding, reasoning and action text in at most three evidenced categories. The registered native MLflow `learner_update_evidence_v1` judge gates publication. Rejection or model/judge failure preserves the prior profile; approval is bound to the baseline and proposal digests. The existing conditional epoch and history rules apply.

Default output is an isolated `.local/judged-learner-intelligence` store, not the live page store. `--proof` uses fictional events and a separate run directory. No HTTP boundary or existing page schema changes. Automatic Story Mode integration and next-session consumption remain unconnected for this producer.

Feed-status migration (October 11): `genie` now accepts `available_not_integrated` in addition to legacy `unavailable_403`. Producer and example report verified access; the renderer handles both and makes clear that the feed still uses SQL. This is a status extension only; profile/evidence formats are unchanged. Availability reflects the saved diagnostic, not a continuous Genie health check.

Genie integration migration (October 11, additive): live profiles may include optional `analysis` with conversation_id, response_id, source_url, summary and evidence_digest; update records may include source_url. Legacy rules/mock producers omit them. Genie edits only constrained prose; code keeps metrics, identity and evidence authoritative. The consumer renders the summary and allowlisted source link. Status adds checking/analyzing/connected/unavailable for active Genie processing. Pending Story Mode evidence is buffered separately from published profiles. Run the unchanged contracts command plus the expanded offline intelligence suite.

Synthetic cloud test (October 11, additive): `scripts/test_synthetic_cloud_flow.py` writes only fictional events to the fixed separate `workspace.magneto.synthetic_learner_e2e_v1` table. `learner_genie.generate_synthetic_test` retains `synthetic: true` and uses a separate cache and profile store. Production ingestion and `generate` still reject synthetic events/profiles. No schema or live-learner selection changes. `GET /api/learner-profile?mode=synthetic-test` reads the last successful validated test artifact without triggering live refresh. Open `/learn/?profile=synthetic-test#intelligence` to render it through the existing About me consumer, explicitly labeled fictional. Both preview modes skip live feed-status refresh. See `reports/synthetic-cloud-flow/README.md` for proof and resume commands.

## Research reflection migration (October 11)

The localhost bridge now invokes `scripts/learner_reflection.py` in its existing asynchronous worker after confirmed outcome ingestion. This replaces Genie-owned category updates. No browser/director/harness payload changes or cloud job deployment. Restart the local server to load the new worker. One server writer remains required.

`learner_episodes.py` constructs deterministic session views of normalized evidence: exact duplicate IDs collapse, conflicting duplicates fail, timestamps order by their actual timezone-aware instant, and every distinct attempt, support outcome, deferred response, unconfirmed observation and device failure stays in the view. Same-time ordering is explicitly unknown. The current input records outcomes, not full transcripts: prompts, hint content, retry links and session completion are **not inferred**. A session episode is a snapshot of observations so far, not proof that the session ended. Story input snapshots are retained locally under `pending-evidence/raw-story/<content-digest>.json` before normalization. Those richer raw snapshots are archival; the reflection consumes the validated normalized events.

Flow: normalized evidence → session episodes → bounded category queries → existing research library HYBRID search + current Delta eligibility → proposal with observation/passages/applicability → native MLflow `learner_research_support_v2` judge → conditional profile publication. Library passages are unreviewed research evidence, not approved director guidance. This does not approve research sources/recommendations or change the director's approved-only retrieval gate. Industry intelligence remains in its own existing collection; it is not used to justify teaching efficacy.

Every changed category must cite its own baseline event IDs and at least one supplied passage, with an exact excerpt validated against each passage and a direct/inferred action basis. Inferred suggestions must explain the gap; shared subject matter alone is not support. Full source metadata, immutable source version, original locator, retrieved text, search run IDs, proposal and judgment are saved before publication. The model cannot edit counts or identity. No matching passages produces an explicit empty proposal; it can still publish new deterministic observations. Judge rejection, malformed support, retrieval failure or changed evidence retains the prior profile. There is at most one bounded repair attempt after rejection; both attempts are retained in the audit. Inputs over the MVP size bound fail explicitly instead of being silently truncated.

Genie receives the derived profile only for a summary. Its summary is optional; it cannot replace the judged categories or block their publication. The LLM judge assesses support and applicability, not demonstrated educational benefit. Suggestions remain hypotheses to test, not an automatic teaching intervention.

The additive optional profile `reflection` property contains the MLflow run ID, input digest and proposal digest. `research-profile.example.json` is synthetic. The existing browser reader ignores this extra provenance and continues to render the unchanged category fields; no data-collection UI was added. The local record also holds `last_reflection` and `reflection_version` so a provenance-only pass checkpoints without creating another epoch. Prior epochs retain their original reflection references. Profiles/checkpoints remain local; this migration does not create a distributed learner database.

Find the full audit in `/Shared/magneto-research` → Runs → matching reflection ID → Artifacts → `reflection/audit.json`, or locally `<profile-store>/reflections/<id>.json`. Search runs are separate linked operational runs. The audit artifact is uploaded before profile publication; the run's `publication.json` records the resulting epoch. A crash after publication but before that final artifact is recoverable from the local profile's reflection ID/checkpoint. Rejections are retained as audit artifacts. A failed retrieval may have only the failed search run and failed parent run, with no complete reflection artifact. No-new-evidence skips retrieval and model calls in the live bridge. Source-only changes do not automatically reevaluate learners; that requires a deliberate future reprocessing policy.

Excerpt matching normalizes PDF whitespace, typographic quotes, Unicode compatibility characters and in-word typesetting hyphens. It does not normalize words or paraphrases. Original source text and generated excerpts remain in the audit.
