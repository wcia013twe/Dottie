A concrete Databricks implementation example

Self-optimizing football chatbot demonstrates expert labeling, judge alignment, and GEPA prompt optimization. The transferable pattern is expert feedback driving a scored improvement loop. It is a technical walkthrough in another domain; it does not prove effectiveness for education.

Recommended implementation boundary

Use two operational loops: an orchestrator reads a profile and returns a validated lesson action; an updater derives proposed profile revisions from outcome events. Add a periodic prompt optimization task to improve shared instructions across representative examples. This task can live in the updater experiment, so a third MLflow experiment is optional.

Retain structured outcome events and numeric skill estimates in governed tables. Managed memory can carry readable facts and hypotheses without making relevance search the authority for mastery. Start with one learner model appropriate to the task rather than combining BKT and FSRS immediately.

What is available versus what is connected?

The repository has orchestrator tracing and a verified synthetic updater trace. Persistent learner memory, personal session analysis and automated optimization are not connected. Databricks documentation describes available features; this research did not confirm preview entitlements or provision these services in your workspace.

The scoring target must include delayed independent performance. A better LLM judge score is evidence about the agent's output, not proof that a learner learned more.
